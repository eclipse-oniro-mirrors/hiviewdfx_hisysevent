# KP-002: 紧凑结构体布局是跨进程二进制协议

## 严重级别
fatal

## 来源
事件编码二进制协议与 C ABI 契约

**问题详情**：
- 严重级别：严重（Major）
- 影响范围：hiview 数据源解码端、所有使用 C 结构体的调用方、跨版本兼容
- 出现概率：必现（若改布局）
- 故障恢复：恢复布局并重新对齐 hiview

## 问题回顾
事件数据经 `RawData` 编码后通过 Unix Domain Socket 投递给 hiview 数据源。其中 `HiSysEventHeader`、`TraceInfo`、`ParamValueType`（`raw_data_base_def.h`）以 `#pragma pack(1)` 紧凑布局直接 `memcpy` 进字节流，hiview 端按相同布局解码。

同时，C 公共结构体（`HiSysEventParam`、`HiSysEventQueryRule`、`HiSysEventWatchRule`、`HiSysEventWatcher`、`HiSysEventRecordC` 等）的字段顺序与定长数组大小是对下游 C 调用方的 ABI 契约。

修改字段顺序、类型、位域宽度或定长数组大小，会同时破坏：与 hiview 的二进制协议、C ABI 兼容、`.map` 中已导出的 mangled 符号。

## 代码陷阱模式

**陷阱：把紧凑结构体/C 结构体当普通内部数据结构调整（调字段顺序、合并字段、改位域、扩大数组）。**

隐蔽性：
1. 组件内编码/解码自测可能仍通过（两端同步改）。
2. 但 hiview 数据源（另一仓库）未同步改，导致解码错位或崩溃。
3. 下游 C 调用方按旧布局分配内存，字段错位。
4. mangled name 变化导致 `.map` 失配、链接失败。

## 高风险代码区域

### 1. raw_data_base_def.h（与 hiview 的二进制协议）
- **文件**: `interfaces/native/innerkits/hisysevent/include/raw_data_base_def.h`
- `HiSysEventHeader`：`domain[17]`、`name[33]`、`timestamp(u64)`、`timeZone(u8)`、`uid(u32)`、`pid(u32)`、`tid(u32)`、`id(u64)`、`type:2`、`isTraceOpened:1`。
- `TraceInfo`：`traceFlag(u8)`、`traceId(u64)`、`spanId(u32)`、`pSpanId(u32)`。
- `ParamValueType`：`isArray:1`、`valueType:4`、`valueByteCnt:3`。
- `ValueType`/`EncodeType` 枚举值。
- **禁止**：改字段顺序、类型、位域宽度、数组大小、枚举值。

### 2. C 公共结构体（ABI 契约）
- **文件**: `hisysevent_c.h`（`HiSysEventParam`、`MAX_LENGTH_OF_PARAM_NAME`）、`hisysevent_manager_c.h`（`HiSysEventQueryArg`、`HiSysEventQueryRule`、`HiSysEventWatchRule`、`HiSysEventWatcher`、`HiSysEventQueryCallback`、`MAX_NUMBER_OF_EVENT_LIST`、`MAX_NUMBER_OF_WATCH_EVENT_LIST`）、`hisysevent_record_c.h`（`HiSysEventRecordC` 及其定长数组）。
- **禁止**：改字段顺序、类型、定长数组大小、宏值。

### 3. IPC 数据结构（Parcel 布局）
- **文件**: `adapter/native/idl/include/`（`query_argument.h`、`sys_event_rule.h`、`sys_event_query_rule.h`）。
- `sequenceable` 的 Parcel 序列化顺序与字段布局不可变。

## 检查规则

修改任何上述结构体前，必须确认：

### Step 1: 判断是否真的需要改布局
绝大多数需求可通过新增字段（而非改现有字段）或新增结构体满足。

### Step 2: 若必须新增字段
- 紧凑结构体新增字段会改变 hiview 解码偏移 → 必须与 hiview 仓库协同，确认跨版本兼容方案。
- C 结构体新增字段破坏 ABI → 考虑新增独立结构体/函数而非改现有。

### Step 3: 验证
```sh
# 编码兼容：写入事件后用未改动的 hiview 解码（板侧），确认字段正确
hdc shell hisysevent -r -d HIVIEWDFX
# 符号兼容：mangled name 变化会导致 .map 失配
nm out/rk3568/.../libhisysevent.so | grep HiSysEventHeader
```

## 正确模式

需要扩展事件信息时，优先新增独立字段并保证向后兼容，绝不重排现有字段：

```cpp
// 正确：在末尾追加字段（仍需与 hiview 协同解码端）
#pragma pack(1)
struct HiSysEventHeader {
    // ... 现有字段保持不变 ...
    uint8_t newField; // 仅在确认 hiview 解码端同步支持时追加
};
#pragma pack()
```

## 反面模式

```cpp
// 错误：调换字段顺序 / 合并位域 / 改数组大小
struct HiSysEventHeader {
    char name[MAX_EVENT_NAME_LENGTH + 1]; // 调到前面 → hiview 解码错位
    char domain[MAX_DOMAIN_LENGTH + 1];
    ...
};
```
