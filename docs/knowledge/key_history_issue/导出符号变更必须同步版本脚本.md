# KP-001: 导出符号变更必须同步版本脚本

## 严重级别
fatal

## 来源
innerapi 库符号可见性管理

**问题详情**：
- 严重级别：严重（Major）
- 影响范围：依赖 libhisysevent / libhisyseventmanager 的所有子系统与三方应用
- 出现概率：必现（若未同步）
- 故障恢复：重新构建并修正 .map

## 问题回顾
`libhisysevent` 与 `libhisyseventmanager` 均使用版本脚本（`libhisysevent.map` / `libhisyseventmanager.map`）控制导出符号：`global` 段列出允许导出的 C++ mangled 符号与 `extern "C"` 符号，`local: *` 隐藏其余所有符号。

当新增公共 API（如新增 `HiSysEvent` 方法、`OH_HiSysEvent_*` C 函数）或新增 `Encoded`/`HiSysEventRecord` 等被下游链接的符号时，若忘记在 `.map` 的 `global` 段登记，符号被 `local: *` 隐藏，下游链接期或运行期找不到符号，导致编译失败或运行时 `dlsym` 失败。

## 代码陷阱模式

**陷阱：新增/重命名导出符号后未同步 `.map`，符号被 `local: *` 默认隐藏。**

隐蔽性：
1. 组件内自测（静态库 `*_static_lib_for_tdd`）不受 `.map` 影响，自测通过。
2. 只有当其它子系统以动态库方式链接时才暴露。
3. `innerapi_tags`（`chipsetsdk_sp`/`platformsdk`/`sasdk`）意味着符号是跨子系统契约。

## 高风险代码区域

### 1. libhisysevent.map
- **文件**: `interfaces/native/innerkits/hisysevent/libhisysevent.map`
- 导出 `HiSysEvent::*`、`Encoded::*`、`WriteController::*`、`StringFilter::*`、`EventSocketFactory::*` 等 C++ 符号及 `HiSysEvent_Write`/`OH_HiSysEvent_Write` C 符号。
- **风险点**: 新增公共方法或被 NAPI/ANI/Rust 直接调用的内部符号必须登记。

### 2. libhisyseventmanager.map
- **文件**: `interfaces/native/innerkits/hisysevent_manager/libhisyseventmanager.map`
- 导出 `HiSysEventManager::*`、`HiSysEventRecord::*`、`HiSysEventBaseManager::*`、`HiSysEventRecordConvertor::*` 及 `OH_HiSysEvent_*` C 符号。
- **风险点**: 新增 `OH_HiSysEvent_*` C 接口或 `HiSysEventRecord` 取值方法必须登记。

## 检查规则

修改公共符号时，必须执行：

### Step 1: 确认符号是否在 global 段
对新增的导出函数/方法，确认其 mangled name 已在对应 `.map` 的 `global` 段。

### Step 2: 构建后验证导出表
```sh
prebuilts/build-tools/linux-x86/bin/ninja -C out/rk3568 libhisysevent
nm -D --defined-only out/rk3568/base/hiviewdfx/hisysevent/libhisysevent.so | grep <符号名>
readelf --dyn-syms out/rk3568/.../libhisysevent.so | grep <符号名>
```
确认新符号出现在动态符号表且未被 `local` 隐藏。

### Step 3: 确认下游可链接
若符号被 NAPI/ANI/Rust/c_wrapper 或其它子系统直接引用，构建这些目标确认链接通过。

## 正确模式

```gn
# BUILD.gn 中已配置 version_script
ohos_shared_library("libhisysevent") {
    version_script = "libhisysevent.map"
    ...
}
```

```text
// libhisysevent.map：新增导出符号登记到 global
{
  global:
    extern "C++" {
        "OHOS::HiviewDFX::HiSysEvent::NewPublicMethod(...)";
    };
    extern "C" {
        "OH_HiSysEvent_NewApi";
    };
  local:
    *;
};
```

## 反面模式

```text
// 错误：新增了 OH_HiSysEvent_NewApi 实现与头文件声明，
// 但未在 libhisysevent.map 登记 → 被 local:* 隐藏，下游 dlsym 失败
```
